# 2.8 需求：画中画面板整理、文件详情框、画面交互统一

过程文档，做完后删除；仍有效的规则并入 README 与 docs/dev-guidelines.zh-CN.md。未说明之处按开发约定执行。
分三组：A、B 互不依赖可并行；C 改动 `pipview.*`，在 A 合并之后做。

## A. 画中画面板与播放列表（pipview / piplist / pipfav / pip / filebar）

### A1 操作面板布局
```
│              文件名（居中，点击定位）      [固定] │   标题行
│ (▶) ━━━━━━━●──────────────────────  0:04 / 0:06 │   播放行（与文件栏同构）
│ |◀  ▶|  循环  区段                   过滤  收藏 │   按钮行
```
- 三行共用同一个左右内边距：播放键、「上一个」与左边对齐；时间、「收藏列表」、「固定」与右边对齐。按钮尺寸成体系（按钮行、播放键同一规格）。
- 标题行：文件名居中（三列网格，做法同文件栏：过长省略中间，放不下时向左让出、不压按钮）；右端只有「固定」，它比按钮行的按钮小一号（约 24px 按钮、15px 图标），离上缘、右缘的距离与内边距一致，不贴边。
- 按钮行：左组依次是上一个、下一个、循环范围、只播放书签区段；右组是过滤、收藏列表（收藏在最右）。去掉「定位」按钮。过滤的二级按钮、收藏菜单随按钮弹出，不出窗口。
- 窗口变窄、变矮时的收起规则不变（收起时间、按钮等分缩小、依次收起按钮行与标题行），任何尺寸不溢出。
- 用 `getBoundingClientRect` 断言对齐（左缘、右缘各自相等，文件名中心在行中心），并截图自查观感。

### A2 点击文件名定位（画中画标题行、主窗口文件栏标题行，两处同一表现）
- 视频、音频的文件名是按钮：指针为手形，悬停、键盘聚焦有高亮，Enter / 点击 = 主窗口定位到该文件所在的页（必要时切书，即现在「定位」的行为）；完整路径仍在 title。按钮上的文字不可选中。
- 文件栏作用于它显示的那个文件（当前文件）；显示的是图片时文件名仍是普通文字（可选中，不可点）。画中画作用于当前曲目。
- 去掉文件栏标题行的「定位」按钮（`addHead` 的 locate）。播放列表每行的「定位」保留。
- 两处用同一段逻辑与样式（共用一个小函数 / 一组样式即可，不必做成组件）。

### A3 一个「固定」开关
- 功能栏（标题行 + 操作面板）与播放列表的固定 / 浮出合并为标题行上的一个「固定」按钮，统一切换：固定 = 功能栏停靠在画面下方 + 列表停靠在右侧；不固定 = 两者都收起，靠悬停浮出。标题行不再有「播放列表」按钮。
- 一个布局类偏好，默认不固定；旧的 `pipDock`、`pipList` 不再使用。
- 窗口太窄时固定的列表仍按浮出的方式显示（现有规则保留）。↑ ↓ 选择时临时浮出列表的行为保留。

### A4 浮出与收起
- 指针在功能栏所在的高度范围内（面板下部，不论功能栏是否已浮出）时，靠近右缘不触发播放列表，保证功能栏最右的按钮点得到；列表已浮出、指针在列表上移动时不受此限。
- 功能栏、列表的显示与收起都带停留延迟和淡出，快速划过不弹出、不抖动，观感与主窗口左右侧栏一致。
- 列表淡入完成之前不弹文件详情框（规则见 B2，这里接入）。

### A5 切换固定时保持画面大小
- 真实画中画窗口里切换「固定」时，内容区（画面）的宽高保持不变，改为调整窗口大小：固定时宽度加上列表宽、高度加上功能栏高，取消时减回。
- 用画中画窗口的 `resizeBy` / `resizeTo`，在按钮点击的手势里同步调用（先查文档确认限制：需要用户激活、是否消耗激活、尺寸上限）。
- 不闪：布局切换与窗口尺寸变化落在同一帧（等窗口的 `resize` 再切换类，设超时兜底），不出现画面先被挤小再弹回。逐帧动画若因"每次手势只能调整一次"不可行则不做。
- 浏览器拒绝、被屏幕边界或尺寸上限截断时退回让内容区让出空间的方式，不报错。普通容器（测试）里不调整窗口。
- 停靠的列表用固定宽度（不随窗口宽度比例变化），目标尺寸的计算做成纯函数（`core/pip.mjs`）并测试；真实窗口的观感列入人工验收（开发约定 8）。

### A6 窗口标题
- 画中画窗口的标题（`document.title`）是当前曲目的文件名（与标题行显示的相同），随曲目变化更新；没有曲目时是应用名。

### A7 播放列表的行
- 书签标记改用缩略图书签角标的同一画法（`marks/pagemarks.mjs` 的 badge 与 `.mk` 样式：书签图标，多于一个带数量，有区段书签时区段配色），共用同一个函数和样式，行内只调整定位；队列项需提供书签数量。没有书签时留空位，各行对齐。
- 「定位」「移除」叠在行的右端（绝对定位），不占文件名的宽度：文件名占满到行尾；两个按钮紧挨（约 24px 一个），只在悬停 / 选中 / 聚焦的项上显示，带与该行底色一致的接近不透明底（左侧渐变过渡），当前曲目行、选中行同样看得清。

## B. 文件详情框、侧栏时机、字幕（filecard / panel / dock / subtitles / shell）

### B1 详情框布局（全部详情框：主窗口各列表与画中画播放列表）
- 去掉「类型 · 时间 / 时长 · 正在播放」这一行。
- 文件名最多两行（类型图标在首行左侧）；两行仍放不下时省略中间、保留开头和结尾（结尾常带序号）。
- 进度条与条上的书签、区段标记保留，播放中为强调色、位置实时更新；时长未知时不画进度条。
- 书签上弹出的详情框：当前书签的指示器由「竖线 + 三角」改为只有一个朝下的三角，在进度条上方，尖端对准该书签的时间点；这一对标记高亮、最下一行的时间和名称保留。

### B2 面板完全显示后才弹详情框
- 浮出的面板（主窗口右侧缩略图栏、左侧书架书签栏，画中画的播放列表）淡入完成之前，它里面的项不弹详情框；淡入完成时指针仍停在某项上，这时再弹。固定停靠的面板不受影响。
- 判断放在 `ctx.fileCard` 一处（如 attach 时给出"面板是否已完全显示"的判断），各面板不各写一套；主窗口浮出面板若没有淡入过渡则补上（与淡出对称）。

### B3 字幕字号
- 所有位置的字幕字号加大约 20%：页内视频、全屏、音频卡片（3 行仍正好放满、不裁切）。画中画里的字号与位置见 C4。

## C. 画面交互与提示统一（scrub / hud / keys / volume / media.tap / pipview，A 之后）

### C1 同一套画面交互
- 页内视频（含全屏）、音频卡片、画中画内容区经同一个底层交互接入：单击（不含拖动）= 播放 / 暂停，横向拖动 = 快进 / 快退，提示显示在该画面所在处。差异只是参数：竖向拖动是否滚动正文（主窗口滚动，画中画不滚动）、命中区域（音频卡片是字幕区，画中画的音频是整个内容区）。把 `scrub.mjs` 的两条路径与正文点按（`ctx.media.tap`）收拢到一个登记接口。
- 画中画内容区单击 = 播放 / 暂停当前曲目（按钮、占位的「在画中画显示」、带 `data-nodrag` 的元素除外；拖动之后不算点击）。主窗口现有规则不变。

### C2 同一个提示浮层
- `hud.mjs` 做成可按宿主创建的同一个组件（同样的结构与样式：图标、文字、音量条），主窗口一个、每个画中画面板一个（在内容区中上部，随内容区大小适当缩放）；去掉 `pipview` 自己的简版 `.pip-hud`。
- 操作在哪个窗口发生，提示就显示在哪个窗口：画中画窗口里的按键（← → / A D、Q / E）、时间处的快退 / 快进按钮、内容区拖动的提示都在画中画里；主窗口里的操作照旧在主窗口（全屏时在全屏的播放器里）。

### C3 画中画里音频的阶梯音柱
- 没有字幕可显示时的音柱横向铺满内容区宽度，并带与字幕相同的半透明深色底（圆角），不直接叠在图上。

### C4 画中画里的字幕
- 字号与 B3 同比例加大；位置上移（离内容区底部约 `max(28px, 12%)`），浮出的功能栏盖住时仍让到它上面。
