# MangaView 开发约定

改动前先读这份文档。它记录的是这个项目**一贯的要求**，新需求里没有重复说明的地方，一律按这里执行。
新增约定时写成"应该怎样"的规则，不写改动历史。

## 1. 定位

- 桌面端、本地、离线可用的漫画 / 条漫阅读器（Chrome / Edge 的 PWA）。不做移动端专属布局、在线源、云同步。
- 纯原生 ES 模块，无构建步骤，无第三方依赖。不引入框架、打包器或 npm 包。
- 阅读优先：任何功能都不能打断阅读、遮挡正文或改变正文的滚动位置。
- 对用户保持简单：能不新增状态、列表、设置项就不新增；内部再复杂，用户看到的概念也要少。

## 2. 硬盘与性能

用户的漫画主要放在机械硬盘上，同时也要顾及固态硬盘的寿命。

- 只读取当前真正需要的内容：可见的正文优先，其次是阅读方向上的少量邻页；封面、缩略图只加载可见部分。
- 建索引、刷新、扫描只列目录和读元数据，不为此读原图内容。
- 磁盘访问串行或严格限并发；后台任务（检查文件夹、生成封面等）让位于当前阅读，在空闲时进行。
- 同一个文件不读第二遍：读过的结果要缓存复用（如缩略图的会话内存缓存）。缓存必须有上限和失效条件。
- 不做高频写入：位置、筛选条件等持久化都要去抖；不在滚动、按键的路径上写 IndexedDB。
- 不把原图或原尺寸位图存进浏览器存储，只存压缩后的小缩略图。
- 按"数千本书、每本数百页"设计：列表要虚拟化、增量更新，避免每次变化都全量重建或出现 O(n²) 的路径。
- 存储空间接近配额时提醒用户清理旧记录。
- 没有确实的收益就不做优化。

## 3. 数据

- 不上传、不修改、不复制用户的原文件。
- 找不到文件夹的书永远不自动删除；只有用户明确操作才删除记录，且要先确认。
- 刷新、权限被拒、硬盘未连接都不能造成书签、标签、进度、阅读位置丢失。
- 一本书由 1..n 个"源"（文件夹）组成；同一个源可以属于多本书。刷新和恢复以源为单位，结果作用到所有引用它的书。全部源都找不到才算过期。
- 页面靠页名识别（书签、阅读位置都依赖它），页名在一本书内必须唯一且稳定。
- 存档结构可以演进，不要求完整兼容，但旧记录、旧偏好、旧备份加载时不能报错或白屏：读入时归一化，坏数据跳过。
- "设置 / 布局"类偏好要登记到 `ctx.prefs`，以便"还原默认设置"能重置；用户数据（书、书签、标签、预设）不在重置范围内。
- 开发和测试中不读取用户真实的浏览器配置、存档或漫画目录，只用测试自己生成的临时数据。

## 4. 交互

- **鼠标与键盘一致**：鼠标悬停和键盘焦点是同一个"选中"状态，显示相同的内容和样式。
- **不靠悬停触发动作**：悬停只做提示和高亮，跳转、切换、打开全屏等动作一律要点击或按键。
- **边缘呼出**：四条边的触发距离是同一个值（`app.mjs` 的 `EDGE`），配合短暂停留延迟防误触；改动只改这一处。
- **默认不打扰**：侧栏默认关闭，浮动界面在鼠标移开后收起，不常驻悬浮图标。
- **打开界面时落在当前内容上**：打开书架聚焦当前书并滚到它，打开全屏缩略图选中当前页，而不是落在搜索框或列表开头。
- **再点一次即关闭**：已激活的入口（页签、开关按钮、快捷键）再次触发就关闭对应界面，回到阅读。
- **列表操作不闪烁**：删除、移动、改名等单项操作只更新受影响的项，其余项的位置、已加载的图片、滚动位置和焦点保持不动。
- **筛选要让人知道**：筛选条件会持久化，也会限定切书和书签列表的范围，所以生效时要有明显提示和一键清除；空状态要区分"确实没有"和"被筛选掉了"。
- **数量多时不铺开**：标签、预设等可能很多的列表要折叠、限高或提供搜索，不挤占主要内容。
- **危险操作先确认**，并说明不会删除原文件。
- 列表类界面提供"普通网格（默认）/ 瀑布流"切换，选择要记住。
- 全局快捷键在输入框内、对话框打开时、带 Ctrl / Meta 时让路。改键位要同步帮助列表和 README。

## 5. 布局与视觉

- **位置稳定**：状态变化（有无筛选、数字位数变化、按钮禁用、联想结果增减）不能让其他元素移动或改变尺寸。做法：始终占位（禁用而不是移除）、为数字预留固定宽度、角标和计数用绝对定位叠加、浮层不参与布局。
- **不溢出**：任何窗口宽度下内容都不能冲出面板；窄窗口（约 360–500px）要换行或收成图标。
- **主内容优先**：工具区保持一行以内，次要选项收进可折叠面板或弹出层，列表区始终占绝大部分高度。
- **工具行用图标**：按钮只放图标，文字放进 tooltip 和 aria-label；有展开 / 收起状态的按钮带方向箭头，直接弹出菜单的按钮不带。
- **一个图标一个含义**：同一界面内不同功能不共用图标。新图标加到 `index.html` 的 sprite，沿用 24×24 线条风格。
- **同类控件同一风格**：下拉菜单、弹出层、开关、按钮各用一套样式，不混用原生控件外观和自绘外观。
- **密集布局里的强调用缩小 + 描边**，不放大（放大会遮挡邻居）。
- **点击区域要够大**：独占一行的入口做成块级按钮。
- 按钮、页签、开关等控件的文字不可被选中；书名、文件名等需要复制的文本保持可选。
- 浮层要显示在 `<dialog>` 之上时用 popover / top layer，不靠 z-index。
- 不加装饰性的动态效果（光晕、取色延伸等）干扰阅读。

## 6. 文案

- 四种语言（中 / 英 / 日 / 韩）同时补齐，位于 `lang.mjs` 或各模块的 `extend()`。
- 文案简短；同一个概念全应用只用一个叫法（如"操作栏""散图图集""导入为单个作品"），改名要全局统一，包括 tooltip、帮助列表和 README。
- 书签（bookmark，页内位置）和标签（tag，书的分类）是两个概念，不要混用。

## 7. 开发流程

- 每个行为改动都要有测试：纯逻辑放 `tests/core.test.mjs`，界面行为放 `tests/*.browser.mjs`。布局类要求用 `getBoundingClientRect` 断言（位置稳定要连 left / top / width 一起比），并截图自查观感。
- 提交前跑完 `tests/` 下全部测试。浏览器测试同时最多跑 3 个，否则会因时序抖动超时。
- 发版同时修改 `index.html` 的 `<title>` 和 `sw.js` 的 `cacheName`；新增源文件要加进 `sw.js` 的 `shell` 列表。
- 行为变化要同步 `README.zh-CN.md` 和 `README.md`。
- 开发推送到 `2.0` 分支；`main` 即线上（GitHub Pages），人工验收后再合并。
- 自动化覆盖不到、需人工验收的：真实机械硬盘上的大图库、安装后的离线冷启动、中键自动滚动、已安装应用的窗口边框。

## 8. 容易踩的坑

- 模块之间通过 `ctx` 上的函数取数据（如 `ctx.readingList`、`ctx.matchFilter`、`ctx.atEdge`），不要各自复制一份逻辑或常量，否则会各改各的、逐渐不一致。
- 更具体的 CSS 选择器会悄悄盖掉控件自己的尺寸（如"行内按钮"的规则命中了开关）；给通用规则加排除条件，控件自身写明确尺寸。
- 预留宽度不要用隐藏的占位子元素（会进入 `textContent`，影响读屏和测试），用 `::after{content:attr(...)}` 之类的方式。
- 先删库、后清内存的顺序会被后台任务把记录写回去：删除时先从内存移除，持久化前检查记录是否仍然存在。
- 测试里读位置或样式要等过渡结束（`:active` 缩放、旋转动画、popover 的异步 `toggle`）；断言落在稳定的属性上，而不是易变的文本。
- 浏览器拿不到磁盘绝对路径，文件夹只能靠名称、相对路径和内容摘要识别；没有句柄时的匹配要保守，宁可让用户确认也不要猜。
