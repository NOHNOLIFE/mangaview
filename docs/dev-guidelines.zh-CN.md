# MangaView 开发约定

改动前先读这份文档。它记录的是这个项目**一贯的要求**，新需求里没有重复说明的地方，一律按这里执行。
新增约定时写成"应该怎样"的规则，不写改动历史。

## 0. 红线：禁止接触开发者的真实数据

**任何情况下都不得读取、打开、列出、截图或以其他方式使用开发者本机的真实数据**，包括：

- 开发者日常使用的浏览器配置目录（Chrome / Edge 的 User Data、已安装的 MangaView 应用的 IndexedDB、localStorage、缓存）；
- 开发者的漫画、图片目录及其中任何文件、文件名、缩略图；
- 开发者导出的备份文件。

原因：这些数据可能包含 R18 等敏感内容。AI 工具一旦读到，可能触发平台的风控策略，严重时会导致开发者的 AI 账号被封禁。这不是一般的隐私建议，而是必须严格执行的硬性规定。

具体要求：

- 调试、复现问题、验收一律用测试自己生成的临时数据：独立的临时浏览器配置（`--user-data-dir` 指向临时目录）+ 自动生成的测试图片。现有 `tests/*.browser.mjs` 都是这样做的，新测试照此办理。
- 不要用开发者的默认浏览器配置启动浏览器，不要附加到开发者正在运行的浏览器，不要对开发者的真实窗口截图。
- 需要了解旧存档的结构时，从代码和 git 历史推断，并自己构造旧格式的测试记录；不要去看真实存档。
- 问题只在开发者的真实数据上出现时，请开发者自己描述现象或提供脱敏后的最小样例，不要自行去读。
- 拿不准某个路径或文件是不是真实数据时，按"是"处理，先问开发者。

## 1. 定位

- 桌面端、本地、离线可用的漫画 / 条漫阅读器（Chrome / Edge 的 PWA），浏览器原生能播的视频、音频作为页排在同一条长条里。不做移动端专属布局、在线源、云同步。
- 纯原生 ES 模块，无构建步骤，无第三方依赖。不引入框架、打包器或 npm 包。
- 阅读优先：任何功能都不能打断阅读、遮挡正文或改变正文的滚动位置。
- 对用户保持简单：能不新增状态、列表、设置项就不新增；内部再复杂，用户看到的概念也要少。

## 2. 硬盘与性能

用户的漫画主要放在机械硬盘上，同时也要顾及固态硬盘的寿命。

- 只读取当前真正需要的内容：可见的正文优先，其次是阅读方向上的少量邻页；封面、缩略图只加载可见部分。
- 建索引、刷新、扫描只列目录和读元数据，不为此读原图内容。
- 磁盘访问串行或严格限并发；后台任务（检查文件夹、生成封面等）让位于当前阅读，在空闲时进行。
- 浏览器的文件读取可能挂起不返回：限并发的队列里，读文件、解码都要有超时（按失败处理并让出名额），被丢弃的任务立即让出名额；单个文件卡住不能拖住其他图片。
- 已保存的句柄可能整体失效（常见于浏览器更新后：操作挂起、不报错，同一文件夹重新选择得到的新句柄却正常）：对已保存句柄的一切操作（读文件、列目录、`isSameEntry`、查询权限）都经 `src/core/sources.mjs` 的 `timed` 限时。
- 失效和读得慢要分开判断：启动和刷新前用不碰磁盘的 `queryPermission` 并行探测（`probe`），它都不返回才算失效（本次会话不再重试），几秒内一次判定完，不逐个等硬盘超时；读文件、列目录超时只算暂时读不到，过一段时间重试。
- 句柄失效时主动提示并说明原因（浏览器版本有变化时写明是更新所致），提示里直接给恢复入口；不按浏览器版本预先作废存档，多数更新并不影响句柄。
- 恢复只接回已有记录，不新增书；任何恢复入口（批量、单本、定位原文件）都把所选文件夹里其他失效的书、卷和散图一并接回。
- 同一个文件不读第二遍：读过的结果要缓存复用（如缩略图的会话内存缓存）。缓存必须有上限和失效条件。
- 不做高频写入：位置、筛选条件等持久化都要去抖；不在滚动、按键的路径上写 IndexedDB。
- 不把原图或原尺寸位图存进浏览器存储，只存压缩后的小缩略图。
- 视频、音频：是不是内容、是否受支持只按扩展名判断，导入、刷新不为此打开文件。只有与视窗相交的媒体持有源（对象 URL，浏览器按需读取，不整体读进内存），离开视窗即卸载、释放解码器，不预加载相邻媒体。要打开文件才知道的结果（能否播放、帧尺寸、时长、能否截取画面）连同文件的大小和修改时间记入页记录，文件没变就不再探测；检查文件是否变化只在该页本来就要读取时顺带进行，失败的不在每次启动、刷新时重试。
- 按"数千本书、每本数百页"设计：列表要虚拟化、增量更新，避免每次变化都全量重建或出现 O(n²) 的路径。
- 存储空间接近配额时提醒用户清理旧记录。
- 没有确实的收益就不做优化。

## 3. 数据

- 不上传、不修改、不复制用户的原文件。
- 找不到文件夹的书永远不自动删除；只有用户明确操作才删除记录，且要先确认。
- 刷新、权限被拒、硬盘未连接都不能造成书签、标签、进度、阅读位置丢失。
- 一本书由 1..n 个"源"（文件夹）组成；同一个源可以属于多本书。刷新和恢复以源为单位，结果作用到所有引用它的书。全部源都找不到才算过期。
- 页面靠页名识别（书签、阅读位置都依赖它），页名在一本书内必须唯一且稳定。页名只是内部标识：显示用 `shownName`，读文件用 `fileOf`，不要把页名直接当文件名。
- 全应用只有一个散图图集，散图一律并入它，允许同名图片共存。判断是否同一个文件只用句柄（`isSameEntry`）或元数据，不读图片内容。
- "文件名"排序实际按完整路径逐段自然排序，所有类型的书（单文件夹、合并作品、散图图集）、封面选择、卷的次序共用同一个比较函数（`src/core/model.mjs` 的 `nameOrder`），不为某类书另写一套。界面上仍只叫"文件名"。
- 存档结构可以演进，不要求完整兼容，但旧记录、旧偏好、旧备份加载时不能报错或白屏：读入时归一化，坏数据跳过。
- "设置 / 布局"类偏好要登记到 `ctx.prefs`，以便"还原默认设置"能重置；用户数据（书、书签、标签、预设）不在重置范围内。
- 设置类偏好用 `ctx.prefs.sync(键, apply)` 登记，跨窗口即时同步（别的窗口改动后调用 apply 并派发 `'pref'` 事件）；布局类（侧栏、宽度、列表样式）用 `ctx.prefs.add(键)`，各窗口独立，最后写入的作为下次启动的值。

### 多个窗口

允许同时打开多个窗口（包括同一本书），各窗口各自持有内存中的书目。

- 书目一律经 `ctx.persist` 保存：它在一个读写事务里以存储中的最新记录为基础，只写本窗口改过的字段（`src/core/merge.mjs`）。不要绕过它直接 `library('put')` 整本覆盖（全局操作除外）。
- 书目的新字段不用登记，合并按字段进行，不认识的字段原样保留。需要按条目合并的列表做成带唯一 `id` 的对象数组（如书签），基本类型数组按集合合并；其余字段两个窗口都改了时以后写入的为准。
- 其他窗口的改动经 `'synced'`（书, 字段名）、`'books'` 事件到达，缩略图的变化经 `'thumbs'`（键）到达；只更新受影响的界面项。被别的窗口删除的书不会写回。
- 当前书、阅读位置各窗口独立；阅读位置同一本书以最后写入为准。
- 后台读盘任务（全量检查、封面、文件夹时间等）每一项开始前 `await ctx.disk.turn()`：同时只有持有锁且可见的窗口执行，它关闭或转入后台时由别的窗口接手。
- 全局操作（清空、整体替换、还原默认）先 `await ctx.hold()` 让其他窗口停止写入，完成后 `ctx.reloadOthers(原因)` 让它们重新载入。

## 4. 交互

- **鼠标与键盘一致**：鼠标悬停和键盘焦点是同一个"选中"状态，显示相同的内容和样式。
- **不靠悬停触发动作**：悬停只做提示和高亮，跳转、切换、打开全屏等动作一律要点击或按键。
- **边缘呼出**：四条边的触发距离是同一个值（`src/app.mjs` 的 `EDGE`），配合短暂停留延迟防误触；改动只改这一处。
- **默认不打扰**：侧栏默认关闭，浮动界面在鼠标移开后收起，不常驻悬浮图标。
- **打开界面时落在当前内容上**：打开书架聚焦当前书并滚到它，打开全屏缩略图选中当前页，而不是落在搜索框或列表开头。
- **层叠打开**：在全屏界面上打开书架时，书架盖在上层，全屏界面不关闭；关闭书架回到原界面，焦点回到原列表；下层界面随当前书更新。全屏界面只在跳转或主动关闭时关闭。
- **再点一次即关闭**：已激活的入口（页签、开关按钮、快捷键）再次触发就关闭对应界面，回到阅读。
- **列表操作不闪烁**：删除、移动、改名等单项操作只更新受影响的项，其余项的位置、已加载的图片、滚动位置和焦点保持不动。
- **筛选要让人知道**：筛选条件会持久化，也会限定切书和书签列表的范围，所以生效时要有明显提示和一键清除；空状态要区分"确实没有"和"被筛选掉了"。
- **跟随阅读位置的列表**（如书架书签）：高亮可以随阅读更新，但列表自己滚动只发生在切书、跳转、列表出现时；用户正悬停或刚手动滚动过时不抢滚动位置。
- **相邻的悬停 / 拖放区域要紧贴**：之间不留空隙，命中范围与画出来的范围一致，避免指针经过空白时闪回默认行为。
- **数量多时不铺开**：标签、预设等可能很多的列表要折叠、限高或提供搜索，不挤占主要内容。
- **危险操作先确认**，并说明不会删除原文件。
- 列表类界面提供"普通网格（默认）/ 瀑布流"切换，选择要记住。
- 全局快捷键在输入框内、对话框打开时、带 Ctrl / Meta 时让路。键位只在 `src/panels/help.mjs` 的 `KEYS` / `MORE` 一处登记，改键位要同步那里和 README 的按键表。操作说明用按真实键位排布的图示呈现，而不是长列表。

## 5. 布局与视觉

- **位置稳定**：状态变化（有无筛选、数字位数变化、按钮禁用、联想结果增减）不能让其他元素移动或改变尺寸。做法：始终占位（禁用而不是移除）、为数字预留固定宽度、角标和计数用绝对定位叠加、浮层不参与布局。
- **不溢出**：任何窗口宽度下内容都不能冲出面板；窄窗口（约 360–500px）要换行或收成图标。
- **主内容优先**：工具区保持一行以内，次要选项收进可折叠面板或弹出层，列表区始终占绝大部分高度。
- **工具行用图标**：按钮只放图标，文字放进 tooltip 和 aria-label；有展开 / 收起状态的按钮带方向箭头，直接弹出菜单的按钮不带。
- **一个图标一个含义**：同一界面内不同功能不共用图标。新图标加到 `index.html` 的 sprite（按 id 字母序插入），沿用 24×24 线条风格。
- **同类控件同一风格**：下拉菜单、弹出层、开关、按钮各用一套样式，不混用原生控件外观和自绘外观。
- **密集布局里的强调用缩小 + 描边**，不放大（放大会遮挡邻居）。
- **点击区域要够大**：独占一行的入口做成块级按钮。
- 按钮、页签、开关等控件的文字不可被选中；书名、文件名等需要复制的文本保持可选。
- 覆盖层上的文字要有接近不透明的底色，对比度至少 4.5:1（按背后是白色页面的最坏情况算）。
- 固定尺寸元素上不放随语言变长的文字：图标按钮只放图标，文字放 tooltip 和 aria-label；键位图的键帽只写键名，功能说明放提示框（与 aria-label 一致）。
- 操作说明只写功能名，不写"打开 / 关闭""单击""按下"等常规动作；额外操作（长按、Shift 组合）用各自固定的强调色标出，一条说明不超过两行。
- 浮层要显示在 `<dialog>` 之上时用 popover / top layer，不靠 z-index。
- 不加装饰性的动态效果（光晕、取色延伸等）干扰阅读。

## 6. 文案

- 四种语言（中 / 英 / 日 / 韩）同时补齐，写在各模块自己的 `extend()` 里（见「7. 代码结构」）。
- 文案简短；同一个概念全应用只用一个叫法（如"操作栏""散图图集""导入为单个作品""添加文件夹"）；排序方向统一写"正序 / 反序"，改名要全局统一，包括 tooltip、帮助列表和 README。
- 书签（bookmark，页内位置）和标签（tag，书的分类）是两个概念，不要混用。

## 7. 代码结构

- 根目录只放必须在根的文件：`index.html`、`sw.js`（Service Worker 的作用域取决于它所在的目录，必须在根）、`app.webmanifest`、`icons/`、`local_run.bat`、README、`docs/`、`tests/`、`dist/`（v1 迁移桥）。源码全部放在 `src/` 下，按领域分目录，样式表与同名模块放在同一目录：
  - `src/app.mjs`、`src/style.css`：启动装配（建立 `ctx`、按顺序安装各模块、启动流程，不放功能代码）与全局样式。
  - `src/ui/`：通用界面小工具：`dom`（取元素、建元素与图标按钮、浮层淡出、提示条、长按进度环）、`icons`（往 sprite 登记图标的 `addIcons`）。
  - `src/core/`：不含界面的数据与逻辑：语言（`lang`）、页模型与排序（`model`）、存储（`store`）、多窗口合并（`merge`）、目录扫描与文件访问（`sources`）、过期书匹配（`match`）、区段书签配对（`sections`）、播放顺序（`playlist`）、多窗口协调（`windows`）、偏好登记与跨窗口同步（`prefs`）、当前语言与文案函数（`locale`）、事件表（`events`）、书目与保存（`books`）、旧记录归一化（`normalize`）、过期与句柄状态（`status`）、字幕的解码与解析（`subtitles`）。
  - `src/reader/`：阅读区：正文与缩略图栏（`view`）、缩略图缓存与视频截帧（`thumbs`）、当前书与阅读位置（`session`）、书名进度与提示条等外壳状态及切换语言（`shell`）、右侧缩略图栏的开合与调宽（`panel`）、页面排序（`sort`）、按钮动作表（`actions`）、顶部工具栏（`toolbar`）、底部操作栏（`endbar`）、拖动滚动（`drag`）、正文点击翻屏（`tap`）、按键与长按滚动（`keys`）、专注模式（`focus`）、全屏总览（`overview` 入口、`overview-sheet` 面板外壳与搜索、`overview-pages` 全屏缩略图、`overview-marks` 全屏书架书签）。
  - `src/shelf/`：书架。`shelf` 是唯一入口（装配子模块、重画、列表页签、布局切换），子模块：排序（`sort`）、封面与识别指纹的后台生成（`covercache`）、筛选状态（`filter`，纯逻辑在 `criteria`）、列表布局与焦点（`layout`）、卡片（`card`）、卡片操作按钮（`actions`）、批量操作（`bulk`）、筛选界面（`filterbar`）、搜索预设（`presets`）、存储空间（`storage`）、书名（`rename`）、标签（`tags`）、恢复流程与对话框（`restore`，配对规则在 `pairing`）、共用小工具（`util`）；自定义封面（`cover`）与书的当前封面（`bookcover`，音频的背景）；添加与导入：选择框入口（`pick`）、拖放（`drop`）、导入（`import`）、接回与重建（`relink`）、刷新与检查（`refresh`）、删除（`remove`）。子模块之间经 `shelf` 建立的共享对象 `S` 互相调用。
  - `src/marks/`：书签入口与装配（`bookmarks`）、书签列表的纯逻辑（`list`：排序、区段是否生效、配对坐标、每页标记汇总）、数据操作与跳转（`actions`）、名称与位置文案（`names`）、列表项绘制（`tile`）、就地重命名（`rename`）、书签缩略图（`snap`）、书签面板（`panel`）、书架书签栏（`dock`）、缩略图上的标记（`pagemarks`）、PotPlayer 书签（`pbf`）；播放器进度条上的书签标记在 `src/media/marks.mjs`，全屏书架书签在 `src/reader/overview-marks.mjs`。
  - `src/media/`：视频、音频播放器。`media` 是唯一入口（建立子模块共享的 `S`、按顺序装配子模块，对外提供 `ctx.media`、`ctx.player` 和正文的 `ctx.view.hooks.media`），子模块：统一音量（`volume`）、播放顺序与循环 / 播完后的切换 / 待接手的播放请求（`order`）、只播放书签区段（`sections`）、播放位置记忆（`position`）、提示浮层（`hud`）、缩略图里的占位（`tile`）、壳的 DOM 与状态显示（`shell`，样式在 `shell.css`）、播放器状态：挂源、失败、播放 / 暂停 / 定位（`player`）、当前媒体与自动播放（`autoplay`）、新窗口播放（`popout`）、外挂字幕的显示与按钮（`subtitles`，样式在 `subtitles.css`）、媒体按键（`keys`）、壳上列表级按钮的登记（`buttons`）；进度条上的书签标记（`marks`，由书签模块安装）。书签标记、占位、提示浮层的样式在 `media.css`。
  - `src/panels/`：设置（`settings`）、导出与导入（`backup`）、键鼠操作图示（`help`）。
- 新模块放进职责对应的目录；出现新的领域时新建目录，不往根目录或 `app.mjs` 里堆。模块之间用相对路径 import。
- 登记类列表一项一行，一行不写多条：`sw.js` 的 `shell` 列表、`index.html` 的图标 sprite（每个 `<symbol>` 一行）、`index.html` 的样式表 `<link>`、`app.mjs` 的导入与模块安装调用。与顺序无关的（`shell` 按路径、sprite 按 id，渐变 `defs` 和 `logo` 在最前）按字母序插入到对应位置，不追加在末尾；有顺序要求的（样式表的层叠、模块的安装顺序）按依赖排列。
- 代码格式由 prettier 统一，配置在 `.prettierrc.json`：提交前运行 `npx prettier@3 --write "src/**/*.{mjs,css}" "tests/**/*.mjs" sw.js`。prettier 只在开发时经 `npx` 运行，不进仓库依赖；`index.html` 和文档不格式化。
- 新增的界面文案放在使用它的模块自己的 `extend()` 里，四种语言一起写；`lang.mjs` 放 `index.html` 静态标签和多个模块共用的文案，不往里堆。
- 新增、移动或删除 `src/` 下的文件要同步 `sw.js` 的 `shell` 列表；`tests/core/sw.test.mjs` 检查该列表正好是根目录的壳文件加 `src/` 下全部 `.mjs` / `.css`，漏登记会失败。
- 测试：纯逻辑按被测模块放 `tests/core/<模块>.test.mjs`，界面行为放 `tests/<功能>.browser.mjs`（按此命名即被测试入口收入，不用另外登记）。统一入口是 `node tests/run.mjs "<浏览器路径>" [名称…]`：先跑核心测试，再逐个串行跑浏览器测试，失败的自动单独重跑一次，最后列出通过 / 失败清单；名称用来只跑文件名包含它的浏览器测试；不带浏览器路径时只跑核心测试（也可直接 `node --test "tests/core/*.test.mjs"`）。

## 8. 开发流程

- 每个行为改动都要有测试：纯逻辑放 `tests/core/<模块>.test.mjs`，界面行为放 `tests/*.browser.mjs`。布局类要求用 `getBoundingClientRect` 断言（位置稳定要连 left / top / width 一起比），并截图自查观感。
- 提交前用 `node tests/run.mjs "<浏览器路径>"` 跑完全部测试。另行手动并行跑浏览器测试时同时最多 3 个，否则会因时序抖动超时。
- 发版同时修改 `index.html` 的 `<title>` 和 `sw.js` 的 `cacheName`；新增源文件要按字母序加进 `sw.js` 的 `shell` 列表（有测试把关）。
- 行为变化要同步 `README.zh-CN.md` 和 `README.md`。
- 开发推送到 `2.0` 分支；`main` 即线上（GitHub Pages），人工验收后再合并。
- 自动化覆盖不到、需人工验收的：真实机械硬盘上的大图库、安装后的离线冷启动、中键自动滚动、已安装应用的窗口边框。

## 9. 容易踩的坑

- 正文里带 `data-nodrag` 的区域（播放器的壳、可选中的文件名等）不参与拖动滚动和点击翻屏；播放器壳上的新按钮登记到 `ctx.player.add`，进度条上的标记经 `ctx.player.decorate` 画在 `.mv-marks` 层里，不另起一套。
- 模块之间通过 `ctx` 上的函数取数据（如 `ctx.readingList`、`ctx.matchFilter`、`ctx.atEdge`），不要各自复制一份逻辑或常量，否则会各改各的、逐渐不一致。
- 更具体的 CSS 选择器会悄悄盖掉控件自己的尺寸（如"行内按钮"的规则命中了开关）；给通用规则加排除条件，控件自身写明确尺寸。
- 预留宽度不要用隐藏的占位子元素（会进入 `textContent`，影响读屏和测试），用 `::after{content:attr(...)}` 之类的方式。
- 先删库、后清内存的顺序会被后台任务把记录写回去：删除时先从内存移除，持久化前检查记录是否仍然存在。
- 测试里读位置或样式要等过渡结束（`:active` 缩放、旋转动画、popover 的异步 `toggle`）；断言落在稳定的属性上，而不是易变的文本。
- `getBoundingClientRect` 包含 transform：选中项缩小（`scale`）后上沿会下移。按画面位置做键盘导航时比较中心点，否则同一行的邻居会被当成上一行。
- 浏览器拿不到磁盘绝对路径，文件夹只能靠名称、相对路径和内容摘要识别；没有句柄时的匹配要保守，宁可让用户确认也不要猜。
